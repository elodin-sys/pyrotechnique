# Agent guide: pyrotechnique

You are editing GPU particle effects for a 3D HDR rocket scene. The tool is
built around a tight loop you can drive entirely from files + CLI.

## The loop

```bash
# 1. Edit an effect (RON) or the scene
#    assets/effects/*.effect | assets/scenes/falcon9.scene.ron

# 2. Capture the scenario you're tuning (deterministic; ~15-60 s wall time)
cargo run -q -- capture --scenario lift-off --compare auto --out shots/lift-off.png

# 3. LOOK at shots/lift-off_vs_target.png (your render left, target photo right)
#    Then iterate.
```

Scenarios: `lift-off`, `ascent`, `max-q`, `mid-flight`, `smoke-trail`.
Useful flags: `--time <s>` (override capture time), `--seed <n>`, `--size WxH`,
`--fps <hz>`, `--scene <path>` (e.g. `scenes/debug_flame_only.scene.ron`).

Rules of thumb:

- Always view the `_vs_target.png` composite, not just your render.
- Wall time scales with capture_time x smoke density; `lift-off` (t=5) is
  fast, `max-q` (t=60) is the slowest.
- Isolate one effect by setting other emitters' `intensity: 0.0` in a copy of
  the scene (see `assets/scenes/debug_flame_only.scene.ron`).

## What to edit where

| Goal | File | Notes |
|---|---|---|
| Colors, brightness, sizes, spawn rate, alpha mode | `assets/effects/*.effect` | Gradients + spawner are plain data; hot-reloads in edit mode |
| Lifetime/velocity/drag constants | same file, `module.expressions` list | Literals referenced by `"#N"` handles from `init_modifiers`/`update_modifiers` |
| Effect *structure* (new modifiers, expressions) | `src/effects/builders.rs` | Then `cargo run -q -- gen-effects` (regenerates all `.effect` files — overwrites hand edits!) |
| Emitter placement/intensity, cameras, scenarios, flight path, sun/exposure/bloom | `assets/scenes/falcon9.scene.ron` | Scene loads at startup (no hot reload; re-run) |
| Sprite textures | `write_soft_circle` / `write_smoke_puff` in builders | Regenerated by `gen-effects` |

**Warning:** `gen-effects` overwrites `assets/effects/*.effect`. If you tuned
values in the RON directly, port them back into `builders.rs` before
regenerating, or don't regenerate.

## HDR intuition (why colors are > 1.0)

The viewport is a physically-exposed HDR camera (EV100 ~13.5-15, TonyMcMapface
tonemap, additive bloom). The sunlit sky is ~1.0; anything that should read as
*emitting light* needs RGB well above 1.0:

- flame core: 20-60x
- orange flame body: 5-25x
- sunlit smoke: ~1.2-2.2x (it reflects, not emits; alpha does the work)

If a flame looks washed-out/pale: raise color intensity or drop `alpha_mode`
to `Add`. If smoke blooms into glare: it's too bright — smoke should stay
`Blend` with modest RGB.

## Effect anatomy (the four built-ins)

- `merlin_core` (Local/Add): the blinding column. Length ~ speed x lifetime.
- `merlin_flame` (Local/Blend): orange divergent cone around the core
  (velocity radiates from a point *behind* the nozzle — move that virtual
  center to change divergence).
- `exhaust_smoke` (Global/Blend): the persistent trail. Spawns behind the
  rocket, hangs for 30-110 s. Its size/alpha gradients set trail width and
  opacity; the emitter's `activity` curve in the scene thins it with altitude.
- `pad_smoke` (Global/Blend, `attach: "world"`): lift-off ground clouds;
  radial blast in the pad plane + buoyancy; `activity` cuts it off at t~12 s.

Shared conventions: exhaust axis is **local -Y** (the emitter entity rotates
-Y onto the scene `direction`); smoke sprites use per-particle random
modulation (`ColorBlendMode::Modulate`) for billow structure.

## Determinism

Captures fix the timestep and seed the CPU (`Random` resource) and GPU
(`prng_seed`) RNGs, and the sim only starts after all assets load. Two runs
with the same seed produce the same simulation; pixels can differ ~0.3% from
GPU blend-order nondeterminism. Treat captures as visually — not bitwise —
reproducible.

## Edit mode (for humans, but useful to know)

`cargo run` opens the editor: emitter list + inspector (spawner rate, alpha
mode, HDR color/size gradient editors), scenario/camera dropdowns, sim-time
scrub, reference-image overlay window, save/reload buttons. External file
edits hot-reload live. The capture CLI never includes the UI.

## Elodin connection

Emitter schema (`position`/`direction`/`intensity`) intentionally mirrors the
`thruster` KDL node in Elodin schematics. Effects tuned here are destined to
become Elodin thruster presets once Elodin is on Bevy/hanabi 0.19+ (hanabi
0.19's `EffectAssetLoader` can load these exact files). Workspace context:
`../docs/crash-course-thruster-particles.md`.
